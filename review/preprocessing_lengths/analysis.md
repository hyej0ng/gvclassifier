# Holdout 전처리 조각 길이 분석

분석 대상: `data/preprocessed/main/{train,validation,inference}.csv.gz`. 원본 입력이나 quarantine은 조각 수에 포함하지 않는다. sub는 바이러스 계열의 동일 조각을 담는 부분집합이므로 main과 더하면 중복 집계된다.

## 핵심 결과

- 전체 4,427,636개 중 정확히 5,000bp는 3,009,091개(67.96%), 5kb 미만은 1,418,545개(32.04%)이다.
- 보존된 길이는 17,506,924,225bp, 원본 contig는 1,349,709개이다. 조각화로 버린 tail은 0bp이다.
- 5kb 미만은 EUK에 가장 많다. 특히 500bp 미만 조각은 거의 모두 EUK/train에 집중되어 있다.

## 조각이 만들어지는 방식

`configs/pipeline.yaml` 및 `scripts/01_preprocessing/04_make_chunks.py` 기준:

1. contig 길이 ≤5,000bp: 그대로 한 조각. 500bp 미만 contig도 보존한다.
2. 긴 contig에서 나머지가 500–4,999bp: 앞부분은 5kb, 나머지는 마지막 tail로 보존한다.
3. 나머지가 1–499bp: 마지막 5kb와 나머지를 합쳐 두 조각으로 재분할한다. 이때 두 조각은 각각 2,500–2,750bp이다.
4. 5kb의 배수: 정확히 5kb 조각만 생성한다.

예: 12,300bp → 5,000 + 5,000 + 2,300bp. 10,200bp → 5,000 + 2,600 + 2,600bp. 300bp contig → 300bp 한 조각. 따라서 `minimum_tail_nt: 500`은 모든 조각의 최소 길이라는 뜻이 아니다.

| inference | 406,682 | 331,600 | 81.5% | 75,082 | 6 |

train의 길이 분포는 validation/inference와 상당히 다르다. split은 genome/similarity group을 먼저 고정한 뒤 chunk를 생성하므로 genome 수의 80/10/10 비율이 chunk 수나 길이 분포까지 보장하지 않는다. 이는 확인된 분포 차이이며, 실제 성능 영향은 별도 평가가 필요하다.

## main/sub 중복과 해석

main의 label 0: ARC/BAC/EUK/MITO/PLASTID. label 1: NCLDV/MIRUS/EVE_NCLDV/EVE_MIRUS/PHAGE. sub는 label 1 조각을 그대로 사용하며 NCLDV+EVE_NCLDV=0, MIRUS+EVE_MIRUS=1, PHAGE=2로 분류한다.

sub 전체는 1,164,195개(정확히 5kb 807,882개, 5kb 미만 356,313개)이며, prefix별 수와 길이 분포는 main의 해당 바이러스 prefix와 같다. sub 파일별 전체 조각은 train 922,226개, validation 116,611개, inference 125,358개이다.

학습에는 `sample_weight = valid_length / genome_total_bp`가 저장되고, 학습 코드가 class weight 및 정규화를 추가한다. 따라서 조각 수가 많은 genome이 그 수만큼 loss를 지배한다고 단정할 수 없다. 다만 모든 조각을 처리하므로 짧은 조각 수는 학습 연산량과 데이터의 길이 구성을 바꾼다.

## 제외된 데이터와 검증

quarantine 원본 contig는 569,319개이며 위 조각 수에서 제외한다. 이 중 EUK는 568,912개다. N 비율, 숙주 genome 겹침, 서로 다른 label의 유사/동일 서열 등으로 제외되며 세부 사유는 `summary.json`에 있다. 원본 inventory의 수를 최종 사용 조각 수와 혼동하지 않아야 한다.

기존 `data/preprocessed/qc_report.json`은 passed=true이며 split 간 겹침과 chunk label 충돌이 보고되지 않았다. 본 분석은 frozen manifest의 길이에 실제 chunk 규칙을 적용해 집계하고, main의 세 CSV를 직접 읽어 길이 분포·서열 길이·좌표 길이를 검증한다. 직접 검증 완료: 실제 main CSV 4,427,636개 모두 manifest 기반 길이 분포와 일치했고, 서열 길이/좌표 길이 오류는 0개였다. 총 bp 및 split별 개수도 기존 QC와 일치했다. 상세 결과는 `verification.json` 참조.
