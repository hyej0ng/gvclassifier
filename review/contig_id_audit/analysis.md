# 전체 데이터 종류의 contig ID 충돌 검사

전처리 파이프라인에 활성화된 10개 데이터 종류를 검사했다. 최종 manifest는 quarantine을 포함한 모든 입력 레코드를 유지하며, 원본 source_summary의 입력 수와 일치함을 확인했다.

서로 다른 record_id가 같은 (genome_id, contig_id)를 갖는지 모든 레코드에서 검사했다. 발견된 충돌은 전체 원본 헤더와 sequence hash로 비교했다. EVE의 174개 충돌 그룹은 모두 서로 다른 서열을 포함하고, 헤더의 | 뒤쪽 토큰 누락과 일치한다.

| 데이터 | 전체 입력 레코드 | 사용 레코드 | 사용 데이터의 contig 키 | 충돌 그룹 | 합쳐져 줄어드는 집계 개수 |
|---|---:|---:|---:|---:|---:|
| ARC | 9,460 | 9,460 | 9,460 | 0 | 0 |
| BAC | 225,723 | 225,486 | 225,486 | 0 | 0 |
| EUK | 1,366,361 | 797,449 | 797,449 | 0 | 0 |
| MITO | 677 | 677 | 677 | 0 | 0 |
| PLASTID | 258 | 257 | 257 | 0 | 0 |
| NCLDV | 277,888 | 277,842 | 277,842 | 0 | 0 |
| MIRUS | 33,987 | 33,930 | 33,930 | 0 | 0 |
| EVE_NCLDV | 1,750 | 1,719 | 783 | 153 | 936 |
| EVE_MIRUS | 312 | 279 | 152 | 21 | 127 |
| PHAGE | 2,612 | 2,610 | 2,610 | 0 | 0 |

전처리 전 전체 입력에서도 EVE 이외 8종류에는 충돌이 없었다. NCLDV는 다른 genome에서 contig 이름이 같아도 genome_id와 결합하면 고유하다. PHAGE의 record_1도 서로 다른 genome_id로 구별되므로 충돌이 아니다.

| 데이터 | Split | 실제 원본 레코드 | 기존 contig 키 | 충돌 그룹 | 집계 감소 |
|---|---|---:|---:|---:|---:|
| EVE_NCLDV | train | 1,433 | 663 | 123 | 770 |
| EVE_NCLDV | validation | 135 | 61 | 15 | 74 |
| EVE_NCLDV | inference | 151 | 59 | 15 | 92 |
| EVE_MIRUS | train | 220 | 116 | 16 | 104 |
| EVE_MIRUS | validation | 31 | 20 | 2 | 11 |
| EVE_MIRUS | inference | 28 | 16 | 3 | 12 |

사용 데이터 기준 EVE_NCLDV는 153개 충돌 그룹에 1,089개 레코드가 포함되고, EVE_MIRUS는 21개 그룹에 148개 레코드가 포함된다. 집계 감소는 데이터 삭제량이 아니라 contig별로 묶을 때의 개수 차이다.

main1/sub1 저장 holdout contig 수를 데이터 종류별로 대조한 15개 항목 모두 원본 레코드 수에서 충돌로 인한 집계 감소를 뺀 값과 일치했다.

기존 학습·전처리·평가 파일과 파이프라인 코드는 변경하지 않았다. 충돌 레코드와 재현 코드는 이 폴더에 저장했다.
